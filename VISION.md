# harmony runtime — Vision

**Big Tech builds better Players. harmony builds a better Play.**

Start with the work: **MOK → PLAYER → PLAY → ROK → REVIEW**.
In a shared Madang, define an objective and turn it into bounded MOKs.
Choose a Player that meets the work's capability, authority, privacy, cost,
capacity and evidence requirements. The Player executes a Play within the
approved scope. A Baton connects authority and evidence; a Challenge makes
insufficient evidence a reason to question the result. A ROK preserves the
work record, and Review informs a better MOK and a better next Play.

The Player Pool can include **Human + AI + Service**: teammates and specialists,
Claude, Codex, Gemini, sovereign or specialist AI, and approved services.
These are examples of the product direction, not delivered integrations or
partnerships. Capacity can inform selection but cannot grant execution authority.

The aim extends beyond coding to design, research, sales and operations.
The current entry point is a local Baton demo for AI-agent development teams
of 1–10. It implements one human decision and one bounded file operation;
Player Pool routing, Challenge workflows, ROK analytics and learning from
Review are not implemented by this release.

Learning should use minimal operational metadata and user-consented signals.
The vision does not require central collection of raw customer code or prompts.
No telemetry collection is added by this release.
